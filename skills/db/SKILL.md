## Навык: запросы к базам данных

Базы работают в Docker-контейнерах. Имя контейнера не угадывай — возьми из
`docker_ps` (у PostgreSQL в образе `postgres`).

### Чтение PostgreSQL — `pg_read(container, database, query)`

Выполняется сразу, без подтверждения: запрос идёт под ролью `agent_ro` без прав
записи в транзакции READ ONLY.

- Один запрос за вызов, без `;` внутри. Нужно несколько — сделай несколько
  вызовов, они идут параллельно.
- Схема: `\l` (базы), `\dt`, `\dn`, `\dv`, `\d <таблица>`. Других метакоманд нет.
- `database` — только имя базы. Не знаешь — начни с `\l` на базе `postgres`.
- Запрос дольше 15 секунд прерывается: ограничивай выборку (`LIMIT`, `count(*)`).
- Ответ с `hint` про `agent_ro` значит, что в этом контейнере роль не настроена.
  Тогда читай через `docker_query` — с подтверждением.

### Остальное — `docker_query(container, command)`, с подтверждением

MySQL, SQLite и Postgres без роли `agent_ro`. Каждый вызов подтверждает
пользователь, поэтому собирай нужное в один-два запроса.

- Запрос передавай через `-c` (psql) или `-e` (mysql); у sqlite3 — последним
  аргументом. Исполнение файла (`-f`) не пропускается.
- Указывай полную команду argv (например: psql -U user -d db -c "SELECT ...").
- Пароль не передавай: внутри контейнера psql ходит по локальному сокету и
  `psql -U <user> -d <db>` работает без него. `PGPASSWORD=...`, `-h localhost` и
  `postgresql://user:pass@...` не нужны и оседают в аудите открытым текстом.

Изменение данных — не этот навык.

Возвращай результат таблицей/структурой; не выдумывай строки, которых нет в выводе.
