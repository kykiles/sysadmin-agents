## Навык: панель remnawave

Ты работаешь с панелью VPN remnawave через её API. Два инструмента:
- `rw_query(script, args)` — **чтение**, выполняется сразу.
- `rw_action(script, args)` — **мутации** (меняют доступ платящего клиента), система
  запрашивает подтверждение автоматически.

Аргументы всегда передавай списком: `rw_query("user-find", ["alice"])`.

### Каталог скриптов

**Чтение (`rw_query`):**
- `user-find <query>` — поиск по telegram_id, числовому id или username → краткая карточка.
- `user-get <id>` — полная карточка (статус, срок, трафик/лимит, sub-ссылка).
- `user-traffic <id>` — использовано/лимит/стратегия сброса, последний онлайн.
- `user-devices <id>` — список HWID-устройств.
- `nodes` — ноды: имя, IP (`address`) и порт, страна, онлайн/офлайн, статус, юзеры онлайн.

**Мутации (`rw_action`, каждая — с подтверждением):**
- `user-extend <id> <days>` — продлить подписку на N дней (от max(текущий срок, сейчас)).
- `user-enable <id>` / `user-disable <id>` — включить / приостановить доступ.
- `user-revoke <id>` — отозвать подписку (ротация ключей и sub-ссылки; старая перестаёт работать).
- `user-reset-traffic <id>` — обнулить счётчик трафика.
- `hwid-reset <id> [hwid]` — сбросить конкретное устройство или все.

Везде `<id>` — числовой `id` из `user-find`. `uuid` скрипты не примут: панель адресует
пользователя числом, и скрипт отобьёт uuid до запроса.

### Правила
- **Всегда сначала найди пользователя и покажи текущее состояние** (`user-find` →
  `user-get <uuid>`), и только потом мутация. Это план: пользователь видит, что и кому меняем.
- Мутацию вызывай по идентификатору из `user-find`, а не по имени — избегаешь ошибки с однофамильцами.
- Не выдумывай результат — возвращай фактический JSON от API и краткий вывод на русском.
- Создание новой подписки/пользователя в этот навык НЕ входит — это делает бот продаж.

### Сырой доступ к API (fallback)
- Сначала пробуй готовые скрипты (`rw_query`/`rw_action`) — они дешевле и надёжнее.
- Если нужного эндпоинта нет среди скриптов — `rw_curl_read` (GET, без подтверждения)
  или `rw_curl_write` (POST/PATCH/DELETE, с подтверждением).
- Задавай только путь (`/api/nodes`), не полный URL: хост и ключ подставляются сами.

Контракт панели (Remnawave 3.x) — не угадывай пути, их всего несколько:
- **Все чтения — только GET.** POST/PATCH/DELETE в этой панели меняют состояние
  и уводят пользователя на подтверждение. Не пробуй читать через POST: эндпоинта
  вида `POST /api/user/list` или `POST /api/user/find-by-telegram-id` здесь нет.
- Префикс — `/api/users` (множественное число). `/api/user/...` не существует.
- Пользователь адресуется **числовым `id`** (`GET /api/users/95`), не `uuid`.
  `uuid` в путях не используется вообще.
- Список: `GET /api/users?size=100`, ответ — `{response: {total, users: [...]}}`.
- Поиск по полю — параметр `filters` (URL-кодированный JSON):
  `GET /api/users?filters=[{"id":"telegramId","value":"923973582"}]`.
  Это и делает `user-find`, отдельного роута по telegram_id нет.
- По имени: `GET /api/users/by-username/<username>`, ответ — объект в `.response`.
- Трафик лежит во вложенном `userTraffic` (`usedTrafficBytes`,
  `lifetimeUsedTrafficBytes`, `onlineAt`), а не в корне карточки.
- Устройства: `GET /api/hwid/devices/<id>` → `{total, devices: [...]}`.
- Мутации: `POST /api/users/<id>/actions/{enable,disable,revoke,reset-traffic}`,
  `PATCH /api/users` с телом `{"id": <число>, ...}`,
  `POST /api/hwid/devices/delete{,-all}` с телом `{"userId": <число>, ...}`.
- Ошибка панели приходит без `.response` — скрипт отдаёт её в stderr и возвращает
  ненулевой код. Пустой ответ при `returncode=0` невозможен: если скрипт молчит и код 0,
  значит операция прошла.
- Swagger в этой инсталляции выключен: `/api-json`, `/api/docs` отдают HTML фронтенда,
  а не схему. Не трать на них вызовы.
- Если GET вернул 404 `Cannot GET ...` — роута нет. Не повторяй тот же путь методом
  POST: подтверждение уйдёт пользователю впустую, а ответ будет тем же 404.

### Плейбук: «клиент оплатил, а доступа нет»
1. `user-find <telegram_id или username>` → возьми `uuid`, посмотри `status`/`expireAt`.
2. Если `status=DISABLED` или срок истёк — покажи это; при необходимости `user-enable`
   и/или `user-extend`.
3. Если жалуется на «не подключается» — `user-devices` (лимит устройств) и `nodes` (ноды живы?).

### Плейбук: «сменить ключ / скомпрометирован»
- `user-get <uuid>` → `user-revoke <uuid>`: выдаст новую sub-ссылку, старую сообщи как недействительную.
