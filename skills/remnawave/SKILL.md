## Навык: панель remnawave

Ты работаешь с панелью VPN remnawave (версия 3.4.x) через её API. Два инструмента:
- `rw_query(script, args)` — **чтение**, выполняется сразу.
- `rw_action(script, args)` — **изменения**. Они меняют доступ платящего клиента, поэтому
  система сама запрашивает подтверждение.

Аргументы всегда передавай списком: `rw_query("user-find", ["alice"])`.

### Каталог скриптов

**Чтение (`rw_query`):**
- `user-find <query>` — поиск по telegram_id, числовому id или username → краткая карточка.
- `user-get <id>` — полная карточка: статус, срок, трафик и лимит, лимит устройств, sub-ссылка.
- `user-traffic <id>` — трафик, лимит и стратегия сброса, последний онлайн, первое подключение
  и **последняя нода** (имя, страна, адрес).
- `user-devices <id>` — HWID-устройства: платформа, модель, IP, когда появились.
- `user-history <id>` — последние (до 24) запросы подписки: когда, с какого IP, каким приложением.
- `nodes` — ноды: имя, IP (`address`) и порт, страна, онлайн/офлайн, статус, юзеры онлайн.

**Изменения (`rw_action`, каждое — с подтверждением):**
- `user-extend <id> <days>` — продлить на N дней. Активному срок прибавляется к текущему,
  истёкшему считается от сегодня, и клиент снова становится ACTIVE.
- `user-enable <id>` / `user-disable <id>` — включить / приостановить доступ.
- `user-revoke <id>` — отозвать подписку: новые ключи и новая sub-ссылка, старая перестаёт работать.
- `user-reset-traffic <id>` — обнулить счётчик трафика.
- `hwid-reset <id> [hwid]` — сбросить одно устройство или все.

Везде `<id>` — числовой `id` из `user-find`. Панель адресует клиента только им: поля `uuid`
у пользователя в 3.4 нет, а `shortUuid` — это часть sub-ссылки, в пути он не годится.

### Правила
- **Сначала найди клиента и покажи текущее состояние** (`user-find` → при нужде `user-get <id>`),
  и только потом изменение. Пользователь подтверждает действие по этому состоянию — без него
  он не видит, что и кому меняется.
- Изменение вызывай по `id` из `user-find`, а не по имени: username бывают похожими, id — нет.
- Не выдумывай результат: возвращай фактические данные от API и краткий вывод на русском.
- Создание клиента или новой подписки в этот навык не входит — это делает бот продаж.

### Если готового скрипта нет
Скрипты дешевле и надёжнее, поэтому сначала пробуй их. Если нужного среди них нет:
`rw_curl_read` (GET, без подтверждения) или `rw_curl_write` (POST/PATCH/DELETE, с подтверждением),
путь без хоста (`/api/nodes`). **Прежде чем писать путь, прочитай `references/api.md`**
(`read_skill_file`) — там проверенные пути 3.4, и угадывать их не нужно.

### Плейбук: «клиент оплатил, а доступа нет»
1. `user-find <telegram_id или username>` → возьми `id`, посмотри `status` и `expireAt`.
2. `DISABLED` — предложи `user-enable`. Истёк срок (`EXPIRED`) — `user-extend`: он сам вернёт ACTIVE.
3. `LIMITED` — кончился трафик: покажи `user-traffic`, предложи `user-reset-traffic`.

### Плейбук: «не подключается»
1. `user-find` → `id`; статус должен быть `ACTIVE`, иначе см. плейбук выше.
2. `user-history <id>` — тянет ли клиент подписку вообще и каким приложением. Пусто — приложение
   до панели не доходит (неверная ссылка, её не импортировали, блокировка у клиента).
3. `user-devices <id>` против `hwidDeviceLimit` из `user-get` — не упёрся ли в лимит устройств.
4. `user-traffic <id>` — последняя нода; `nodes` — жива ли она.

### Плейбук: «сменить ключ / ключ утёк»
- `user-get <id>` → `user-revoke <id>`: выдаст новую sub-ссылку, старую сообщи как недействительную.
