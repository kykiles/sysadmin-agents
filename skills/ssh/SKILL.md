## Навык: удалённая нода по SSH

Ты работаешь не на мастер-сервере, а на **удалённой ноде**. Адрес ноды (IP или hostname)
даётся в задаче — сам его не выдумывай и не подбирай. Если адреса нет, верни это как
ошибку: искать его — дело Директора.

Инструменты (SSH здесь только транспорт, вся логика — твоя):
- `ssh_query` — **только чтение** на ноде (docker ps/logs/inspect/stats, systemctl status,
  journalctl, df, free, uptime, ss, ip show). Выполняется сразу.
- `ssh_exec` — **любые команды, включая изменяющие** (restart, compose up, apt upgrade).
  Опасен, система запросит подтверждение пользователя автоматически.

### Общие правила
- Команду передавай списком аргументов: `["docker", "ps", "-a"]`.
- Пайпы/grep/циклы — через `["sh", "-c", "..."]`; если внутри всё read-only,
  `ssh_query` выполнит без подтверждения.
- Всегда `--no-pager` для journalctl и `--no-stream` для `docker stats` — иначе команда
  висит до таймаута.
- Если `ssh_query` вернул «команда не входит в список read-only» — операция изменяющая,
  используй `ssh_exec`.
- Ошибки `Permission denied` / `Connection timed out` не чини сам: доступ (ключ на
  мастере, IP мастера в allow-list ноды) настраивает пользователь. Сообщи факт.
- Не выдумывай вывод — только фактический stdout/stderr и код возврата.

### Плейбук: «нода недоступна / timeout в панели»
1. Живость канала: `["uptime"]` через `ssh_query` — если SSH не отвечает, дальше не иди,
   сообщи, что нода недоступна и на каком шаге (timeout, refused, permission).
2. Контейнеры: `["docker", "ps", "-a"]` — смотри State/ExitCode/RestartCount у
   `remnanode` и рядом стоящих.
3. Логи ноды: `["docker", "logs", "--tail", "200", "remnanode"]`.
4. Логи Xray: `["docker", "logs", "--tail", "200", "xray"]`, либо внутри контейнера
   `/var/log/xray/error.log` — сначала проверь, какие контейнеры реально есть.
5. Ресурсы: `["df", "-h"]`, `["free", "-m"]`, `["uptime"]` — переполненный диск и OOM
   дают ровно такие «короткие ошибки» в панели.
6. Сеть/порты: `["ss", "-tlnp"]` — слушает ли нода свой порт.
7. Демон docker: `["systemctl", "status", "docker"]`, `["journalctl", "-u", "docker",
   "-n", "100", "--no-pager"]`.

### Плейбук: администрирование
- Перезапуск контейнера: `ssh_exec ["docker", "restart", "remnanode"]`.
- Пересборка compose-проекта: сначала `ssh_query ["ls", "<dir>"]` — убедись, что путь и
  `docker-compose.yml` на месте, потом
  `ssh_exec ["sh", "-c", "cd <dir> && docker compose up -d --build"]`.
- Обновление системы: `ssh_exec ["sh", "-c", "apt-get update && apt-get -y upgrade"]`;
  перед этим проверь свободное место `df -h`.
- Любое изменение — сначала осмотр через `ssh_query`, потом одно точечное `ssh_exec`.
  Не «на всякий случай» и не пачкой.

### Плейбук: cron на ноде
1. Посмотри текущий крон: `ssh_query ["crontab", "-l"]` (пустой вывод — задач нет).
2. Добавляй, НЕ затирая существующее:
   `ssh_exec ["sh", "-c", "(crontab -l 2>/dev/null; echo '0 4 * * * /usr/bin/docker restart remnanode') | crontab -"]`.
   Без `crontab -l` впереди `| crontab -` сотрёт все прежние задачи.
3. Проверь результат: снова `ssh_query ["crontab", "-l"]`.
- `crontab -e` не используй — он интерактивный, команда повиснет до таймаута.
- В строке cron `%` означает перевод строки: в командах экранируй как `\%`.
- Путь к бинарю пиши полный (`/usr/bin/docker`) — у cron скудный `PATH`.
