# Промпт-видение — источник принципов, а не спецификация реализации

Архитектурное видение системы было записано в `TASK.md` (промпт, подготовленный с помощью Gemini; файл удалён 16.09.2026, решение от него не зависит). Мы принимаем из него **принципы** — один долгоживущий Директор, stateless-агенты под задачу, файловые скиллы, принцип айсберга, veto на опасных действиях, Telegram как основной интерфейс — но не буквальные технические предписания.

Конкретно отвергнуты три предписания промпта, потому что уже написанное строго мощнее:

- **Скиллы как каталог `SKILL.md` + опциональный `tools.py`**, а не `.json` с единственным `bash_command`: плейбук на markdown несёт стратегию, а `tools.py` даёт типизированные инструменты и декларацию доступа к хосту (`ACCESS`).
- **SQLite для памяти** (`facts`, `dialog`, `tasks`), а не `rank_bm25` поверх плоского `experience.json`: индексы, upsert-дедуп и запросы по областям вместо полного перечитывания файла.
- **`risk_level` на уровне инструмента** (`Safety.DANGEROUS`), а не на уровне скилла: один скилл содержит и читающие, и меняющие операции, подтверждение нужно только вторым.
